# Перечень персональных данных и мест их хранения

Составлено инженерией по фактической схеме базы (миграции `0001`–`0022`, неделя 16) для
документов оператора (4-business-legal 4.1 п. 7, 3-engineering 7.3). Это черновик для юриста:
категории и сроки сверяет юрист, решения Ф-5, Ф-6, Ф-19 — основатель. Сверка с кодом:
`src/assistant/api/account_data.py` (реестр всех таблиц; тест падает, если таблица не учтена).

## 1. Где хранится

| Место | Что | Где физически | Шифрование |
|---|---|---|---|
| Основная база PostgreSQL | все таблицы ниже | управляемый Postgres в Казахстане (Ф-16) | диск (managed); прикладное AES-256-GCM: БИН/ИИН и банковские реквизиты профиля компании (`company_profiles.bin_iin_enc`, `bank_enc`), сессия Telegram (`imports.session_enc`) |
| Объектное хранилище (S3) | оригиналы файлов, логотип/подпись/печать, файлы КП, архивы «Скачать мои данные» | S3 в Казахстане, ключи `u/<id пользователя>/…` | SSE-KMS (ключи в КЗ) |
| Резервные копии базы и S3 | всё выше | Казахстан | как источник; срок жизни ≤30 дн. |
| Журналы приложения | идентификаторы, длины, коды исходов; текст пользователя не пишется; телефоны, e-mail, ИИН/БИН, карты, IBAN, токены вырезаются (`assistant/logs.py`) | Казахстан | — ; 30 дн. |
| Телефон пользователя | локальная копия его данных для работы без сети | устройство | SQLCipher, ключ в Keychain/Keystore |
| Сервисы ИИ за рубежом (Anthropic, OpenAI, Google, Groq) | только фрагмент для одного вызова, с маскировкой, **только при согласии `ai_cross_border`** | США/ЕС (у провайдера) | TLS; срок хранения у провайдера — по договору (Ф-11, ZDR) |
| Push-сервисы Apple/Google | текст напоминания — только при согласии `push_content`; иначе push без текста | у Apple/Google | TLS |

За рубеж ничего не уходит без согласия (consent gate в одном месте, `api/consent_gate.py`).
SMS-шлюз получает номер и код входа.

| Импорт Telegram | `imports` (счётчики, итог; сессия Telegram шифрована, ≤60 мин), `import_seen` (id сообщений Telegram) | перенос «Избранного» без повторов | пока аккаунт жив | удаляется; сессия уничтожается при запросе удаления |
| Жалобы | `feedback` (причина, комментарий, галочка «разрешаю обезличенный пример») | разбор ошибок | пока аккаунт жив | удаляется |
| Траты на ИИ (служебное) | `provider_usage` (задача, модель, токены, стоимость, исход; **без содержимого**), `budgets` (лимит на человека), `usage_counters`, `ai_batch_requests` | лимиты, финучёт | журнал стоимости — для финучёта [срок — юрист/бухгалтер] | `provider_usage` **обезличивается** (`user_id` = NULL, остаются суммы); остальное удаляется |
| Аналитика | `analytics.events` (`user_pseudo` = HMAC от id с отдельным ключом, имя события, свойства без текста, имён, сумм и номеров) | продуктовые метрики (R-40) | 13 мес. [Ф-19] | удаляется по `user_pseudo` |

| Экспорт | `data_exports` + архив в S3 | «Скачать мои данные» | архив 24 ч | удаляется (архив — по ключу) |

| Наследие бота | `trips`, `bookings`, `item_places` | travel-бот | как записи | удаляется |

системный шаблон КП и системные категории трат (строки с `user_id` = NULL).

## 3. Удаление аккаунта (F-27, 7.2)

- Один путь в приложении («Удалить аккаунт и все данные», App Store 5.1.1(v)) и веб-страница
  `/account/delete` (Google Play). Подтверждение: SMS-код при номере, кнопка у анонима.
- Сразу: вход закрыт, сессии и push-токены отозваны, сессия Telegram уничтожена.
- `account.delete_grace_days` = 7 (Ф-6 открыт, 0 или 7): отмена входом в приложение.
- Затем задача `account:purge` (≤24 ч): объекты S3, все строки (реестр выше), события
  аналитики; `provider_usage` обезличивается; `account_deletions.report` — только счётчики.
- Резервные копии истекают ≤30 дн. Восстановления через поддержку нет.

## 4. Открыто

1. Регистрация в реестре операторов и класс (юрист, 4-business-legal 4.1 п. 5).
2. Срок хранения журнала стоимости ИИ (`provider_usage`) после удаления аккаунта (бухгалтер).
3. `audit_log` из 3-engineering 3.8 (вход, экспорт, удаление, доступ к оригиналу) ещё не
   сделан: события удаления пока видны только в `account_deletions`; план реагирования на утечку
   опирается на журналы приложения (30 дн.) и `account_deletions`.
4. Номер телефона не хранится в открытом и в шифрованном виде (`subject_enc` пуст): поэтому
   сервер не может сам прислать SMS на номер аккаунта, телефон присылает номер при удалении.
